Localised text lives in .lcl string tables, one per language, looked up by 0x800f5370. Levels also ship .nog name tables, plain lists of names.

String Table (.lcl)

OffsetSizeTypeDescription
0x004u32String count
0x0416 * nrecord[]Records
varvar-Strings, NUL-terminated UTF-8

Record (16 bytes)

OffsetSizeTypeDescription
0x004u32Hash
0x044offString, from the start of the file
0x084u320
0x0C4u32Tag, the same for every record in a file

The lookup reads only the first two words. It is a binary search that expects the hashes in descending order; a hash it cannot find returns an empty string. Identical strings share one copy.

Name Table (.nog)

OffsetSizeTypeDescription
0x004char[4]Magic NOG
0x044u320
0x084u32File size
0x0C4u32Level hash
0x10varchar[]Names, NUL-terminated, back to back

The header is little-endian on every platform.

In OmegaStudio

  • Byte order is detected from the first byte of the count. Strings are edited in the Properties pane, keyed by hash, and the table exports and imports as JSON.
  • Writing sorts the records by hash, descending, and stores each distinct string once.
  • A .nog opens on its own or inside a disc and exports and imports as JSON. Its names also resolve hashes in the level database and sound bank event names.

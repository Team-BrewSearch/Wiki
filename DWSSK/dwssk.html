Reference for the file formats of DreamWorks Super Star Kartz on console — PlayStation 3, Xbox 360, Wii and 3DS. The game stores its assets in HIG! WAD containers, each holding typed entries addressed by path hash and bucket chain. The DS version of this game runs on a different engine and is documented separately under the Virtuos DS Racing Game Engine.

File Formats

    Conventions

    These hold across every format on this page unless a page says otherwise.

    Byte order
    Big-endian on PS3, Xbox 360 and Wii; little-endian on 3DS. WAD container tables are little-endian on every platform.
    Offsets
    An off is a byte offset from the start of the file or structure. 0 means none.
    Runtime fields
    Fields the game overwrites while loading. The files hold whatever the export tools left there; nothing reads the stored value.
    Units
    World positions in .gdw, .gdi and .gdt are centimetres (scale 0.01). Bone translations in .gds are centimetres scaled by 1/800.
    Textures
    Vertex colours are ARGB on PS3 and RGB on Xbox 360. See the models page for the per-platform layouts.

    WAD Container

    A level's .wad, .wad.mem1 and .wad.vram are read together as one tree. The loader brings up to five such WAD pairs, searching each as .wad then .wad.mem1. Entries are typed and addressed by a CRC-32 path hash. The container layout, header and entry lookup are described on the WAD container page.

    Model Formats

    All model types — .gdw world, .gds skinned, .gdi instanced and .gdt/.gdt.piece tie models — share a 0x50-byte header with materials, textures and shaders, followed by per-kind mesh data. The header, materials system, vertex formats and each mesh type are described on the models page. Skeletons live inside .gds files and are documented on the skeletons page.

    Animation

    Character animation lives in .animpack files beside each character's MASTER folder. Each pack holds multiple clips with bone tracks and optional curves. See the animation pack page.

    Collision and Navigation

    Collision covers .col, .col.piece and collision surfaces (.csd). Navigation meshes (.nav) carry the AI pathfinding data. Level object placement lives in the .bog level database.

    Data Tables

    Gameplay tuning, localised text and fonts. See the tuning tables, localised text, fonts and camera paths pages.

    Verification: The formats on these pages were worked out from the game's own code across the Wii, Xbox 360, PS3 and 3DS executables. Skinning palettes matched the Wii palette builder (0x800cab00) bit-for-bit across 10 characters and 30 random clips. Animation keys decoded bit-identically to the game's decoders across 1,748,046 values. The quaternion-to-matrix routine matches System.Numerics to 2e-8.

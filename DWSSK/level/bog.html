.bog is the name of the level database. Loader: 0x8008e730. The loader checks the header, relocates the file in place, and fills a 0x90-byte level table. No objects are created yet; the tie, shrub and entity code builds them from that table later.

File Header

OffsetSizeTypeDescription
0x004char[4]Magic BOG
0x044u32Version; must be 0x48
0x084u32File size; 0xAC or less loads as an empty database

0x104u32Copied to table +0x00
0x148off, u32A section with no known reader; table +0x04 and +0x08. Empty in every shipped file
0x1C72(off, u32)[18]Sections 0 to 17 (table below)

Every offset counts from the start of the file. Relocating one means adding the file's load address, and the loader leaves a zero offset at zero. The table slot is where the section's pointer goes; its count goes in the word after it.

Some pointers depend on other counts. The tie group and tie pointers, and both tie counts, are set only when there is at least one tie group. The shrub layer, cell and shrub pointers are set only when there is at least one layer, and the points pointer only when there is at least one spline. A class's 0x04 and 0x10, a template's 0x08 and a spline's 0x04 are relocated even when they are zero.

Tie Group (0x14)

Hash, a .gdt hash (entry type 7), a .col hash (type 7, 0 for none), an offset to its ties, and a tie count. The tie loader (0x800f3580) writes the group's address into every tie's 0x40, then swaps 0x04 for the loaded model and 0x08 for the collision.

Every loop over ties steps 0x70 + 12 × n bytes. The hide group is a bit number in the instance's hidden-parts mask (instance + 0xD4). It is 0 for most draws and 1 to 6 for parts such as held items.

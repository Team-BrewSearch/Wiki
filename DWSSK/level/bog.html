.bog is the level database: lights, entities, triggers, splines, and the placements of every tie and shrub. The Wii loader (0x8008e730) checks the header, relocates the file in place and fills a 0x90-byte level table. No objects are created yet; the tie, shrub and entity code builds them from that table later.

Header

OffsetSizeTypeDescription
0x004char[4]Magic BOG
0x044u32Version, 0x48
0x084u32File size; 0xAC or less loads as an empty database
0x0C4u32Level hash; not read by the loader
0x104u32A colour, copied to level table +0x00
0x148off, u32A section with no known reader, level table +0x04 and +0x08; empty in every file
0x1C144(off, u32)[18]Sections 0 to 17: offset, then record count
0xAC4u320

Every offset counts from the start of the file. Relocating one adds the file's load address, and the loader leaves a zero offset at zero.

Some pointers depend on other counts. The tie group and tie pointers, and both tie counts, are set only when there is at least one tie group. The shrub layer, cell and shrub pointers are set only when there is at least one layer, and the points pointer only when there is at least one spline. A class's 0x04 and 0x10, a template's 0x08 and a spline's 0x04 are relocated even when they are zero.

Components and Entity Data

A class lists the components its entities carry. An entity's (or spawner's) data is one blob holding each of its class's components in list order, each size bytes and aligned, and a component's defaults use the same layout. Component data is a run of 4-byte words; known components include AnimCamera, Animation, Bloom, Button, CurveFollower, DamageVolume, Fog, LinearMotion, Mesh, PickUp, RaceMgr, Rotator, SoundPlayer and VisibilityRegion. Some words point at another entity, trigger or spline.

Tie Record

The tie loader (0x800f3580) writes its group's address into every tie's 0x40, then swaps the group's model and collision hashes for the loaded objects.

Every loop over ties steps 0x70 + 12 * n bytes. On little-endian 3DS files the four bytes at 0x64 are reversed, so n sits at 0x65 with the 0xFF at 0x64.

In OmegaStudio

  • The reader needs version 0x48, a size word equal to the file size, zero words at 0x14, 0x18 and 0xAC, and sections 7 to 9 empty. Every pointer must land on a record of the section it names.
  • The database exports and imports as JSON with pointers turned into record indices and component data decoded where the component's word layout is known. The writer rebuilds every offset and count.
  • Tie and shrub placements export as a glTF scene.

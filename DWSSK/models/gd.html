All four model kinds share a 0x50-byte header with materials, textures and shaders, then branch: .gdw is a world mesh, .gdi an instanced shrub, .gdt and .gdt.piece tie meshes, and .gds a skinned mesh that also carries its skeleton. Data starts at 0x50 in every file.

Textures and Shaders

A texture entry is 0x14 bytes, starting with the texture's path hash, which the loader turns into a handle; two floats and two words follow. A shader entry is 0x10 bytes: a vertex and pixel shader pair named by path hash. The loader makes one program per shader entry, and material passes name a program by index.

Materials

A material is 0xAC bytes on Wii, 0xC0 on PS3 and Xbox 360, and 0x8C on 3DS. The files set flag bits 0x1, 0x2 and 0x4; the loader adds 0x10 when any parameter scrolls and 0x20 when a texture record uses the reflection callback.

Units

Positions are drawn with a uniform scale that depends on the kind:

  • .gdw, .gdi and .gdt: 0.01, so the stored values are centimetres.
  • .gds: the float at mesh + 0x04, 8.0 in every file. Bone translations are centimetres scaled by 1/800 into the same space.

The header's bounding radius at 0x40 is in metres, after these scales.

Visibility Tree Node (0x2C bytes)

f32[3] box minimum, f32[3] box maximum, a u32 at 0x18 that the walk does not read, and four child offsets at 0x1C (0 for none). The walk tests each box and records inside, outside or partial per node; a whole subtree takes its parent's answer when the parent is entirely in or out.

Vertex Formats

Wii formats are described with GXSetVtxAttrFmt; PS3, Xbox 360 and 3DS formats with named declaration tables.

Wii

FormatUsed byPositionNormalColourUV
3.gdt, .gdw: 24 bytes, position at 0, normal 12, colour 16, UV 20f32 x 3s8 x 3, /64RGBA8s16 x 2, /1024
4.gdss16 x 3, /16384s8 x 3, /64RGBA8s16 x 2, /1024

Every Wii mesh is indexed: positions, normals, colours and UVs each take a u16 index. .gdt and .gdw point all four arrays into one 24-byte vertex, so a vertex's four indices are always equal.

  • Skinned vertex (32 bytes): s16 position x 3 at 0 (/16384, GQR6), s8 normal x 3 at 6 (/64, GQR7), 3 unused bytes, four joint bytes at 0x0C (top bit ignored), four f32 weights at 0x10.
  • Rigid vertex (10 bytes): the same position and normal.
  • .gdi vertex (36 bytes): f32 position, f32 UV at 12, f32 normal at 20, RGBA8 colour at 32.

3DS

Static, 24 bytes: f32 position x 3 at 0, s16 UV x 2 (/1024) at 12, u8 normal x 3 at 16 as (n - 128) / 127 and a pad byte, RGBA8 colour at 20. The skinned vertex (32 bytes) adds four joint bytes at 24 and four weight bytes at 28.

Wii Display Lists

GX commands zero-padded to 32 bytes. 0x98 draws a triangle strip, 0x90 a triangle list and 0xA0 a fan, followed by a big-endian u16 vertex count and one u16 index per enabled attribute per vertex, in GX order: position, normal, colour, UV. The files use 0x9B (format 3) for .gdt and .gdw and 0x9C (format 4) for .gds.

In OmegaStudio

  • Every kind renders with its textures, each material drawing with the first texture record of pass 0 whose stage is 0. A world splits into one mesh per visibility zone. Positions are shown as stored, without the kind's scale.
  • Skinned models carry their skeleton and play every clip from the .animpack files beside their MASTER folder.
  • Geometry is replaced from glTF (the first LOD). Every model also exports and imports as the JSON and .bin pair the reverse-engineering tools write, which keeps every field and the original block order and padding, so an unchanged model rebuilds byte for byte.

One blob is one clip. Animations sit beside the model blob under the same archive parent and carry one track per model node, in the model's node order. Tracks also name their node.

Header

OffsetSizeTypeDescription
0x004u32Node count, matching the model's node count
0x044u32Clip duration in frames
0x08count * 4u32[]Per-node track offsets, from the start of the blob

The first track begins at 0x08 + node_count * 4.

Track

OffsetSizeTypeDescription
0x000x20char[0x20]Node name, matching a model node
0x204u32Key count
0x2468 * nkey[]Keys

A track is exactly 0x24 + 68 * key_count bytes.

Key (68 bytes)

OffsetSizeTypeDescription
0x000x40f32[16]Matrix, same layout and same space as the bind matrix
0x404f32Time in frames

Semantics

  • Key matrices are absolute, in the same space as the bind pose, not relative to the parent. A joint's local transform at key i is key[i] * inverse(parent_key[i]), at the same key index.
  • Every track in a clip shares the same key times, so no resampling is needed to line the tracks up.
  • Keys are sparse. A 96-frame clip typically stores 25 keys, one every fourth frame.
  • Durations count frames at 60 fps, and key times are whole frames.
Note: A clip starts with a count followed by offsets, exactly the shape of an archive table of contents. A recursive container walk will descend into one and break it apart into individual bone tracks.

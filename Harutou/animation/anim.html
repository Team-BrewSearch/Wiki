One blob is one clip. Clips sit beside the model in the same archive table and carry one track per model node, each track naming its node.

Header

OffsetSizeTypeDescription
0x004u32Node count, matching the model's
0x044u32Duration in frames
0x084 * nodesu32[]Track offsets, from the start of the blob

The first track starts right after the offset table, at 0x08 + 4 * node_count.

Track

OffsetSizeTypeDescription
0x000x20char[0x20]Node name, matching a model node
0x204u32Key count
0x2468 * nkey[n]Keys

A track is exactly 0x24 + 68 * key_count bytes.

Key (68 bytes)

OffsetSizeTypeDescription
0x000x40f32[16]Matrix, same layout and same space as the bind matrix
0x404f32Time in frames

Semantics

  • Key matrices are absolute, in bind-pose space, not relative to the parent. A joint's local transform at key i is key[i] * inverse(parent_key[i]).
  • Every track in a clip shares the same key times, so tracks line up without resampling.
  • Keys are sparse. A 96-frame clip typically stores 25 keys, one every fourth frame.
  • Frames run at 60 fps, and key times are whole frames.
Note: A clip starts with a count followed by offsets, the same shape as an archive table. Recognise clips before recursing into a table, or a walk will split them into bone tracks.

In OmegaStudio

  • A blob is a clip when it is at least 16 bytes, the node count is 1 to 4095, the duration is 1 to 99,999 frames, the first track offset equals 8 + 4 * node_count, and the first track's key count is 1 to 99,999 and fits the blob.
  • Every clip in a table plays on the model in that table. Tracks drive bones by name, ignoring case.
  • Playback runs at 60 fps and blends the two keys either side of the current frame.

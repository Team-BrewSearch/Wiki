Every data/*.bin file is a recursively nested table of contents. A table is a count, a list of offsets and the payloads they point at. There is no magic number, no version field and no filename anywhere. Children are often tables themselves, to varying depths.

Layout

+----------------------+   <-- table base
| Count                |       u32, number of child slots
+----------------------+   <-- base + 4
| Offset table         |       count * u32, relative to the table base
+----------------------+
| 0xFE padding         |       up to the first child
+----------------------+
| Child payloads       |       each starting on a 32-byte boundary
+----------------------+   <-- end of the parent's slot
OffsetSizeTypeDescription
0x004u32Child slot count
0x044 * countu32[count]Child offsets, relative to this table's own base
varvaru8[]0xFE padding up to the first child
varvar-Child payloads

Slots

  • Offsets are relative to the table that lists them, not to the start of the file.
  • Offsets are not sorted.
  • Offsets may repeat. Two slots with the same offset are aliases of one shared payload, not two copies.
  • An offset of 0 is an empty slot.
  • A child runs to the next larger distinct offset. The last child runs to the end of its parent.

Payload Identification

Leaves carry no names or type tags, so a payload is identified by its magic or its structure: ringtex2 textures, models, animation clips and Ogg and RIFF audio.

Note: An animation clip starts with a count followed by offsets, which is structurally the same as a table of contents. A recursive walk has to recognise clips before it recurses, or it splits each one into its bone tracks.

Most parent tables also end with a 40 to 96 byte block of 0D 0A followed by zeros. It holds no asset data and behaves as an end marker.

In OmegaStudio

A slot is treated as a table only when it is not already a recognised payload (texture, model, clip, or anything another plugin claims, such as Ogg or WAV) and it passes every check:

  • The slot is at least 8 bytes and the count is between 1 and 8191.
  • The offset table fits the slot, and every offset lies inside it.
  • Every non-zero offset clears the header, so it is at least 4 + 4 * count.
  • Every byte between the end of the offset table and the first child is 0xFE.
  • At least one slot is non-empty.

The whole file is held in memory, which caps an archive at 4 GiB.

Saving rebuilds the file from the root. Each table writes its count and offsets, pads with 0xFE up to the next 32-byte boundary, then writes its children, each padded with 0x00 to 32 bytes. Aliased slots are written once and keep pointing at the same copy. Replacing one slot of an alias pair gives it a payload of its own; the other slot keeps the original.

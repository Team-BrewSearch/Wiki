A model blob holds one character or object: a flat list of nodes, each either a bone or a mesh, followed by any number of embedded ringtex2 textures. The skeleton is rebuilt from parent indices stored on the bones. Animation clips are separate blobs in the same archive table as the model.

Header

OffsetSizeTypeDescription
0x004u32Version, always 1
0x044u32Node count
0x084u32Unknown
0x0C4u32Embedded texture count, at most 16
0x100x40u32[16]Offsets of the embedded textures, one per texture
0x504 * nodesu32[]Node offsets

Offsets count from the start of the blob. The first node starts right after the node table, at 0x50 + 4 * node_count, with no padding. A node runs to the next node offset; the last node runs to the first texture, or to the end of the blob when there are no textures.

Node Type

No type tag is stored. A node is a mesh when the four bytes at +0x70 are "Mate", the start of its first material name. Every other node is a bone.

Bone Node

OffsetSizeTypeDescription
0x000x70char[0x70]Bone name, null padded
0x704u32related: parent node index plus one
0x7412-Unknown
0x804u32Node index of the mesh this bone skins
0x844u32Weight count
0x880x40f32[16]World bind matrix
0xC80x40f32[16]Inverse bind matrix, unreliable (see below)
0x1080x48-Unknown
0x1508 * n{u32, f32}[n]Skin weights: skin vertex index, weight

A bone node is exactly 0x150 + 8 * weight_count bytes, for every bone of every character in the retail data.

Skeleton

parent = related - 1 rebuilds the whole hierarchy with no special cases: Lshoulder under Spine1, Lupleg under Hips, hair chains under Head, skirt chains under Hips. The first node, ABone, is the root. Bones prefixed DBS_ and DBE_ mark the start and end of dynamic-bone chains for hair, skirts, ribbons and collars.

Note: The matrix at 0xC8 is the inverse of the bind matrix for ordinary bones, but a few weightless DBS_ anchors store something else there. Invert the bind matrix at 0x88 instead; OmegaStudio never reads 0xC8.

The material count is the number of entries before the first zero in the table at 0x30. Triangles are handed to materials in order: the first material takes the first tri_counts[0] triangles, the next takes the following tri_counts[1], and so on.

The count block sits 4 bytes after the last material record. OmegaStudio's reader still locates it by scanning from 0x70 up to 0x400 for four words where the first two are equal and between 1 and 220 - 1 and the third equals the summed triangle count.

Draw Stream

A plain triangle list with no index buffer. Each triangle stores three full 40-byte vertices and a 28-byte trailer, 148 bytes in all.

Vertex (40 bytes)

OffsetSizeTypeDescription
0x0012f32[3]Position, always equal to positions[vertex_id]
0x0C12f32[3]Normal, unit length
0x188f32[2]UV, origin top-left
0x204u8[4]Vertex colour, B, G, R, A. Neutral grey throughout the retail data, typically 0x808080FF
0x244u16[2]vertex_id, stored twice

0x184-Unknown

Skinning

vertex_id links the draw stream to the skin. Bone weight lists index the skin-space position and normal arrays, not the draw vertices. No vertex has more than four bone influences.

In OmegaStudio

  • A blob is a model when it is at least 0x60 bytes, the version is 1, the node count is 1 to 4095, the texture count is at most 64, and the first node offset equals 0x50 + 4 * node_count.
  • For each skin vertex the reader keeps the four heaviest influences and normalises them.
  • Replacing from glTF fills the model's meshes in order. Extra glTF meshes are merged into the last mesh, and extra materials into the last material. Joints bind to bones by name, ignoring case; an unmatched joint takes the bone at the same place in the list.
  • The writer limits a mesh to 65,535 vertices, since vertex_id is 16-bit, and 16 materials. It writes vertex_id twice, recomputes each face normal from its triangle, and zeroes the rest of the trailer.
  • Weight lists are rewritten for the bones of each replaced mesh. Everything else, unknown fields and the 0xCC bytes after the count block included, is copied from the original. Nodes are rebuilt back to back after the node table, with the textures after them.

A model blob holds one character or object: a flat list of nodes that are either bones or meshes, plus any number of ringtex2 textures at the end. The skeleton is rebuilt from parent indices stored on the bones. Animations are separate blobs sitting beside the model under the same archive parent.

Header

OffsetSizeTypeDescription
0x004u32Version, always 1
0x044u32Node count
0x084u32Not reverse-engineered
0x0C4u32Texture count
0x100x40u32[]Offsets of embedded ringtex2 blobs
0x50node_count * 4u32[]Node offsets, 0xFE padded up to the first node

All offsets are from the start of the blob, and the first node begins at 0x50 + node_count * 4. A node's length runs to the next node offset; the last node runs to the first texture offset if the blob has textures, otherwise to the end of the blob.

Node Classification

Every node begins with a 0x70-byte name field. A node is a mesh when the four bytes at +0x70 are "Mate", the start of its first material name; otherwise it is a bone. No type tag is stored.

Bone Node

OffsetSizeTypeDescription
0x000x70char[0x70]Bone name, null padded
0x704u32related - parent node index plus one
0x7412-Not reverse-engineered
0x804u32Index of the mesh node this bone skins
0x844u32Weight count
0x880x40f32[16]World bind matrix
0xC80x40f32[16]Inverse bind matrix - unreliable, see below
0x1080x48-Not reverse-engineered
0x1508 * n{u32, f32}[]Skin weights: vertex index, weight

A bone node is exactly 0x150 + 8 * weight_count bytes, which holds for every bone of every character in the retail data.

Skeleton

parent = related - 1 reconstructs the whole hierarchy with no special cases, and the result is anatomically correct: Lshoulder under Spine1, Lupleg under Hips, hair chains under Head, skirt chains under Hips. The first node, ABone, is the root. Bones prefixed DBS_ or DBE_ are dynamic-bone chain start and end markers, used for hair, skirt, ribbons and collars.

Note: The matrix at 0xC8 is the inverse bind matrix for ordinary bones, but a handful of weightless DBS_ anchors store something there that is not the inverse of their bind matrix. Invert the bind matrix at 0x88 instead of trusting it.

Mesh Node

OffsetSizeTypeDescription
0x000x20char[0x20]Mesh name, null padded
0x200x10-Not reverse-engineered
0x30up to 0x40u32[]Triangle count per material, terminated by a zero entry, at most 16 entries
0x700x44 eachrecord[]Material records, one per non-zero triangle count
var0x10u32[4]Count block: nverts, nverts, ntris, node index
+0xDC12 * nvertsf32[3][]Skin-space positions
var12 * nvertsf32[3][]Skin-space normals
var148 * ntris-Draw stream

The material count comes from the zero-terminated list at 0x30. The u32 at 0x28 looks like a material count but does not agree with the data.

The count block has no fixed offset, because the material array length varies. It can be found by scanning forward from 0x70 for four consecutive u32 values where the first two are equal and non-zero and the third equals the sum of the per-material triangle counts. Positions begin 0xDC bytes after the start of that block, normals follow immediately, then the draw stream.

Material Record (0x44 bytes)

OffsetSizeTypeDescription
0x000x20char[0x20]Material name, null padded
0x204u32Texture index, 0xFFFFFFFF when untextured
0x2416f32[4]RGBA colour
0x340x10-Not reverse-engineered

Draw Stream

A plain triangle list. There is no index buffer: each triangle carries three full 40-byte vertices followed by a 28-byte trailer, for 148 bytes per triangle.

Draw Vertex (40 bytes)

OffsetSizeTypeDescription
0x0012f32[3]Position, always exactly equal to positions[vertex_id]
0x0C12f32[3]Normal, unit length
0x188f32[2]UV, origin top-left
0x204u8[4]Vertex colour, BGRA. Neutral grey throughout the retail data, typically 0x808080FF
0x244u16[2]vertex_id, stored twice

Triangle Trailer (28 bytes)

OffsetSizeTypeDescription
0x0012f32[3]Face normal
0x0C12f32[3]Face normal again, identical to the first copy
0x184-Not reverse-engineered

vertex_id links the draw stream to the skinning data: bone weight lists index the skin-space position and normal arrays, not the draw vertices.

Triangles are handed to materials in order. The first material takes the first tri_counts[0] faces, the second the next tri_counts[1], and so on. No vertex has more than four bone influences.

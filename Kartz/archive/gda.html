Three files travel together and are useless apart: DWK.gda holds the raw bytes, DWK.gdf the paths, DWK.gdt the byte ranges. Madagascar Kartz ships the same triple as MAD.gda, MAD.gdf and MAD.gdt. Entries are addressed by index: entry n takes its path from the GDF and its byte range from the GDT.

GDF - path table

OffsetSizeTypeDescription
0x004u32Entry count
0x04count * 4u32[count]Offsets into the string pool below, one per entry, relative to the pool
varvarchar[]Null-terminated ASCII paths, backslash-separated

A path looks like Models\Tracks\FarFarAway\FarFarAway.trk.

GDT - offset/size table

OffsetSizeTypeDescription
0x004u32Always 0
0x044u32Entry count, matching the GDF's
0x08count * 8{u32 offset, u32 size}[]Byte range of each entry inside the GDA

An entry is present only when size > 0 and offset + size fits inside the GDA. Anything else is an empty slot.

GDA - data

One contiguous region per GDT entry, with no header of its own. Every entry ends padded with zero bytes up to the next 32-byte boundary.

Shared Content

The shipped archive points multiple GDT entries at the same GDA offset whenever their content is byte-identical: a driver's player and ai texture variants share one texture, two tracks' skyboxes share one zone mesh.

Note: The sharing is load-bearing. An archive rebuilt with a private copy per entry decodes correctly but corrupts the running game, dropping geometry and unrelated character, kart and UI assets. The engine appears to cache a loaded asset by its source GDA offset, so two entries sharing an offset load once rather than twice.

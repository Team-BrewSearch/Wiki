Every Virtuos DS game stores its assets in three files that only work together: the .gda holds the bytes, the .gdf the paths and the .gdt the byte ranges. Super Star Kartz ships them as DWK.gda, DWK.gdf and DWK.gdt; Madagascar Kartz as MAD.*. Entry n takes its path from the GDF and its byte range from the GDT.

GDF: Path Table

OffsetSizeTypeDescription
0x004u32Entry count
0x044 * countu32[count]Path offsets, relative to the string pool that follows
varvarchar[]String pool: null-terminated ASCII paths, backslash-separated

A path looks like Models\Tracks\FarFarAway\FarFarAway.trk.

GDT: Range Table

OffsetSizeTypeDescription
0x004u32Always 0
0x044u32Entry count, equal to the GDF count in retail files
0x088 * count{u32 offset, u32 size}[]Byte range of each entry inside the GDA

An entry exists only when size > 0 and offset + size fits inside the GDA. Anything else is an empty slot.

GDA: Data

One region per non-empty entry, with no header of its own. Each region is zero-padded to the archive's alignment. Both Kartz archives align to 32 bytes.

Shared Content

The Kartz archives point several GDT entries at the same GDA offset whenever their bytes are identical: a driver's player and ai textures share one copy, and two tracks' skyboxes share one scenery mesh.

Note: The sharing is load-bearing. An archive rebuilt with a private copy per entry decodes fine but breaks the running game, which drops geometry and unrelated character, kart and UI assets. The engine appears to cache a loaded asset by its GDA offset, so entries that share an offset load once.

In OmegaStudio

  • The entry count is the smallest of the GDF count, the GDT's stated count and the number of entries the GDT's bytes can hold. Every index below it becomes a row, empty or not.
  • A path whose offset falls outside the GDF reads as empty.
  • The alignment is the largest power of two from 4096 down to 4 that divides every non-zero offset; 32 when every offset is zero, 4 when nothing larger fits.
  • Saving rebuilds the GDA and GDT and leaves the GDF alone. Entries are written in index order, each padded to the alignment. An entry whose bytes match an earlier one (SHA-256, then a full compare) points at the earlier copy, so sharing survives edits. An empty entry gets size 0 at the current end of the data.
  • Before anything is written, the rebuilt pair is read back and every entry is compared with the bytes it should hold.

Every Virtuos DS racing game stores its assets in three files that travel together and are useless apart. The archive stem varies by game: DWK.gda holds the raw bytes, DWK.gdf the paths and DWK.gdt the byte ranges for Super Star Kartz, and Madagascar Kartz ships the same triple as MAD.gda, MAD.gdf and MAD.gdt. Entries are addressed by index: entry n takes its path from the GDF and its byte range from the GDT.

GDF - path table

OffsetSizeTypeDescription
0x004u32Entry count
0x04count * 4u32[count]Offsets into the string pool below, one per entry, relative to the pool
varvarchar[]Null-terminated ASCII paths, backslash-separated

A path looks like Models\Tracks\FarFarAway\FarFarAway.trk.

GDT - offset/size table

OffsetSizeTypeDescription
0x004u32Always 0
0x044u32Entry count; retail files match the GDF count
0x08count * 8{u32 offset, u32 size}[]Byte range of each entry inside the GDA

An entry is present only when size > 0 and offset + size fits inside the GDA. Anything else is an empty slot.

The plugin takes the effective count as the smallest of the GDF path count, the GDT's declared count, and the number of entries the GDT's own bytes can hold. It then keeps an entry for every index below that count, empty or not.

GDA - data

One contiguous region per GDT entry, with no header of its own. The writer pads each non-empty entry with zero bytes up to the archive's detected alignment boundary. The plugin detects the alignment from the entry offsets as the largest power of two from 4096 down to 4 that every non-zero offset shares, falling back to 32 when every offset is zero and to 4 when none fits. Both Kartz archives use 32 bytes.

Shared Content

The two Kartz archives point multiple GDT entries at the same GDA offset whenever their content is byte-identical: a driver's player and ai texture variants share one texture, two tracks' skyboxes share one zone mesh.

The plugin writes this sharing back the same way. Saving rebuilds the .gda and the .gdt; the .gdf name table is read only. The writer hashes each entry's bytes, points every later byte-identical entry at the first copy, pads each non-empty entry to the detected alignment, and then rereads the rebuilt triple and checks every entry's bytes match what it intended to write.

Note: The sharing is load-bearing. An archive rebuilt with a private copy per entry decodes correctly but corrupts the running game, dropping geometry and unrelated character, kart and UI assets. The engine appears to cache a loaded asset by its source GDA offset, so two entries sharing an offset load once rather than twice.

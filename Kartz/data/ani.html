An .ani is one animation clip: a track per animated bone, and per frame one full pose matrix rather than a step. The header comes in a narrow form (Kartz) and a wide form (later games). Bone indices match the .ske of the same character.

Narrow Header (8 bytes)

OffsetSizeTypeDescription
0x002u16Bone count, matching the skeleton
0x022u16Frame count
0x044u328, the header size

Wide Header (20 bytes)

OffsetSizeTypeDescription
0x004u32Bone count
0x044u32Frame count
0x084u3220, the header size
0x0C4u32End of the last track
0x104u320

Body

OffsetSizeTypeDescription
header4 * bonesu32[]Track offset per bone, 0 for a bone the clip does not move
var64 * frames eachi32[16][frames]Tracks: a row-major 4x4 matrix in 20.12 per frame
var12 * (frames - 1)-Zero padding, wide header only

The file is exactly the header, the table and one 64 * frames block per animated bone, plus the wide padding; all 333 Kartz clips match to the byte. Their 20,444 matrices all have the fourth column (0, 0, 0, 4096) and unit-length rotation rows, no two bones share a track, and every clip that pairs with a skeleton by name agrees on the bone count.

Playback

A track's matrix replaces the bone's rest transform for that frame; a bone without a track keeps its rest pose.

Nothing in the file states a frame rate. At 8 frames per second a clip runs as long as it does in the game, so that is the rate OmegaStudio uses. Between frames the viewport blends the two poses either side, turning rotation the short way round and moving translation in a straight line, and the glTF keys use LINEAR interpolation so modelling packages do the same.

In OmegaStudio

  • Bone count 1 to 1024 and frame count 1 to 4096. The narrow header is tried first; the wide one needs +0x10 to be zero.
  • Every non-zero track offset lands in the track region on a frame-block boundary with room for the whole block, and every frame's fourth column is (0, 0, 0, 4096).
  • At least one bone has a track, the file ends exactly after the tracks and padding, a wide header's +0x0C equals the end of the last track, and everything after it is zero.
  • A character plays every clip in its folder whose bone count matches its skeleton. The transport's rate box overrides 8 fps, from 1 to 240, and that rate also spaces the glTF keys.
  • Replacing from glTF reads the rate back from the key spacing, so a clip exported at any rate returns with the frames it left with.

All 348 clips across the five games re-serialise to their original bytes and survive a glTF round trip at 8, 12, 30 and 60 fps alike.

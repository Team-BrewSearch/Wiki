A .car is a rigid model built from the same chunks a track uses, with a tail describing where its wheels sit. The layout below is the two-Kartz shape. The chunk table field moves from +0x10 to +0x14 in the later games, which the plugin detects per file.

File Layout

+0x00  u32    chunk count
+0x04  u32    0 or 3
+0x08  i32    a height, 20.12, matching the y of every point in the wheel block
+0x0C  u32    4
+0x10  u32    0x24, the offset of the chunk table below
+0x14  u32    start of the tail, which is also the end of the last chunk
+0x18  u32    a 12-byte block inside the tail
+0x1C  u32    the same offset again in all but three of the models
+0x20  u32    the wheel block: four points, 20.12, always the last 48 bytes of the file
u32[]         one absolute offset per chunk
chunks, in the .trk chunk format, in table order
tail

The plugin detects the chunk table by reading +0x10, falling back to +0x14, and accepting the table whose offsets fit the file and whose chunks parse. The tail is then read from the parsed chunks, not from a header word: it starts at the end of the last chunk. In the two-Kartz layout that is the value held at +0x14; in the later layout the table field itself is at +0x14.

The parser also rejects a chunk table that starts before 0x20 or whose table runs past the file, requires each chunk offset to land at or after the current chunk end, and rejects a chunk whose display list size is zero, not a multiple of four, or whose texture count is above 4096. A wheel block is present only when the last 48 bytes sit after the last chunk.

Each chunk is a .trk chunk, so the same interpreter draws it and the glTF export and import path works on it unchanged. Twenty-two of the twenty-seven two-Kartz models carry one chunk and a 72-byte tail; the rest carry two chunks or a longer middle block.

Wheel Block

The last 48 bytes hold four points, four wheel positions, each an x, y and z value in 20.12. The height stored at +0x08 matches the y of every wheel point. Wheel values are editable in the plugin as decimal numbers.

Replacement

An import converts glTF through the track path, rebuilds every chunk, writes the chunk table and copies the tail. Writes keep the tail's own bytes and shift header fields that point into the tail by the tail's movement. A chunk with no triangles is copied byte for byte from the template. When the converted geometry matches the geometry already in the file, the plugin leaves the file bytes untouched instead of rebuilding it.

Verification

  • Every .car the plugin reads parses and re-serialises to the bytes it was read from: 103 files across the five games.
  • All 103 survive glTF export and re-import unedited.
  • All 27 two-Kartz models come back byte for byte through glTF.

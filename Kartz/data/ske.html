A .ske holds the skeleton a character model and its animation clips use. It has two record sizes, and the plugin detects which one a file uses. The layout below is the narrow shape the two Kartz games use.

Narrow Layout

+0x00  u32    bone count
+0x04  u32    8, the size of this header
bones, 68 bytes each:
  +0x00  i32     parent index, -1 at the root and always lower than the bone's own index
  +0x04  i32[16] the bone's rest transform, a row-major 4x4 matrix in 20.12

The parser accepts a narrow file only when its length is exactly 8 + 68 * bones, the bone count is between 1 and 1024, the header size word is 8, a parent index is either -1 or less than the bone's own index, and every bone matrix keeps the fourth column at (0, 0, 0, 4096).

size == 8 + 68 * bones holds for all 28 two-Kartz skeletons. Across their 381 bones the fourth column is always correct, the three rotation rows are always unit length, each file has exactly one root, and no bone's parent comes after it.

Wide Layout

+0x00  u32    bone count
+0x04  u32    8, the size of this header
bones, 132 bytes each:
  +0x00  i32      parent index, -1 at the root and always lower than the bone's own index
  +0x04  i32[16]  the bone's placed rest transform, a row-major 4x4 matrix in 20.12
  +0x44  i32[16]  the transform that takes the bone back into its parent, in the same 20.12 form

The parser accepts the wide shape only when the file length is exactly 8 + 132 * bones, with the same bone-count, header-size and parent-index checks. It also requires the fourth column of the first matrix and the fourth column of the second matrix to be (0, 0, 0, 4096).

Transform Chain

A narrow record stores the step from the parent and the parser chains it up the parents to get the bone's world transform. A wide record stores the bone already placed, so the parser uses the first matrix as the world transform. Reading either shape gives the same rest pose, and writing one back keeps the shape it came in.

A skeleton stands in the game's own frame, in which the character's up axis is the third one. Both the viewport and glTF put up on the second axis, so the parser turns every rest transform a quarter turn about x for its consumers and the same quarter turn back when it writes. The turn is applied once in the skeleton model and used by the baked mesh, joint binds, posed frames, model writer and animation roots.

Verification

  • A narrow .ske file also satisfies the loose .trk header test, so the plugin asks the stricter skeleton test first.
  • Every skeleton the plugin reads re-serialises to the bytes it was read from: 43 files across the five games.
  • All 43 skeleton imports across the five games come back byte-identical through glTF, as do all 49 across the two-Kartz pair.

Reference for the file formats used in DreamWorks Super Star Kartz on the Nintendo DS, reverse engineered from the retail archive. Madagascar Kartz is the prequel on the same engine and uses every format documented here unchanged: the same archive triple, the same textures, the same track opcodes and chunk layout, the same tail sections. Differences between the two are noted inline; the only substantive one is how the resource database is split.

File Formats

    Conventions

    These hold across every format on this wiki unless a page says otherwise.

    Byte order
    Little-endian for all integers
    World positions
    20.12 signed fixed point (value * 4096)
    Texture coordinates
    12.4 signed fixed point (value * 16)
    Colours
    RGB555, bit 15 unused in palettes
    Geometry
    Pre-built Nintendo DS GX display list commands
    Paths
    Null-terminated ASCII, backslash-separated
    Transparency
    Magenta colorkey, RGB (255, 0, 255)

    Data Layout

    Both games ship the same set of files in Publish.NDS/: one archive triple holding every asset, and the resource databases that record the order those assets load in.

    Publish.NDS/ ├── DWK.gda - Super Star Kartz archive data, 1770 entries ├── DWK.gdf - path table ├── DWK.gdt - offset/size table ├── MAD.gda - Madagascar Kartz archive data, 1377 entries ├── MAD.gdf - path table ├── MAD.gdt - offset/size table ├── main.rdf [RDF] - resource database ├── ingamemenu.rdf, menupages.rdf [RDF] - Super Star Kartz only ├── maintrack<track>.rdf [RDF] - one per track, Super Star Kartz only └── *.raf [RAF] - one per .rdf, its pointer fixup table

    Entries inside the archive are addressed by path, one per track directory:

    Models\Tracks\FarFarAway\ ├── FarFarAway.trk [TRK] - track geometry ├── FarFarAway.col - collision mesh, not reverse-engineered ├── FarFarAway.bpvs - visibility data, not reverse-engineered └── *.5tx [5TX] - the track's own textures models\tracks\farfaraway\ └── *.zon - scenery bundles, not reverse-engineered

    Nothing in the archive records which files belong to a track. The RDF does: a track's model list names its .col, .trk and .bpvs by archive index, and its texture table gives the slot each .5tx occupies.

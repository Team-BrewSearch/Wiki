A .raf is the pointer fixup table for the RDF of the same name. It has no content of its own: each entry is the offset of a word in the .rdf that holds a file offset and must become a real address when the database loads. Every game ships one .raf beside every .rdf.

Layout

OffsetSizeTypeDescription
0x004u32Entry count
0x044 * countu32[count]Byte offsets into the paired .rdf

The file is exactly 4 + 4 * count bytes, with no magic or padding.

Loading

The game reads the whole .rdf into one block and patches each listed word in place. After that pass every pointer in the database is a live address.

for (u32 o : raf.offsets)
    *(u32*)(rdf + o) += (u32)rdf;

Rules

  • Every offset is a multiple of 4, ends at least four bytes before the end of the .rdf, and appears once.
  • Every word the table points at is a valid in-file offset and never zero. There is no null pointer: a property with nothing to point at is left out of its record.
  • The offsets are not sorted. They follow the order the writer emitted records in.
  • The words they point at are not all 4-byte aligned, because string pointers address a byte-packed pool.
Rewriting: Moving any record inside the .rdf invalidates both the stored offsets and this table, and the pointer set cannot be recovered from the .rdf alone: a plausible file offset looks exactly like an integer property of the same size. A rewritten database has to emit its .raf in the same pass that lays out the records.

In OmegaStudio

The plugin reads .rdf records directly and never opens the .raf. Since the RDF is never rewritten, the RAF never needs to change.

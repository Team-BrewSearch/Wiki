A TRK's texture index points into a table the TRK itself does not contain. That table is built at load time as the level's resources arrive, and its order is authored - it is not archive order, alphabetical order, or anything else derivable from the archive triple. The order is recorded in the .rdf databases that ship beside the archive.

Each has a paired .raf, which is not reverse-engineered.

File Structure

An .rdf opens with a u32 dictionary offset and ends with a string pool. Between them the body is a flat stream of 8-byte entries, each a (u32 type, u32 value) pair. One type is decoded:

TypeMeaning
1value is an archive entry index, into the GDF path table

Entries are 8-byte aligned within a group, but the groups themselves are only 4-byte aligned: a scan has to step by 4 to find the start of a run and by 8 once inside one. Scanning at 8 throughout finds only half the tracks.

The Authored Run

A level's textures appear as type-1 entries in the order the level author listed them. The track model's own textures come first as one uninterrupted run, cleanly bounded by a non-type-1 entry on either side, with no count field ahead of it and no terminator inside it.

That run is not the whole list. After an unrelated stretch of records, the same block continues with the textures the level's scenery bundle loads, and those take slots too:

The bundle directory is the same track name in a different case - all lower-case, beside the track's own mixed-case directory - and holds that level's .zon models. A reversed track has no bundle of its own and shares the forward track's, which is why bundle textures are appended after the track's own rather than taken in file order: FoosaRocks' water is listed long before FoosaRocks_Reverse's run, yet occupies the same relative slots in both.

From Run to Slot Table

Two shipped tracks pin the layout down exactly:

  • Super Star Kartz ShippingFreighter owns 32 textures, its run is 32 long, and its highest drawn slot is 32. There is nowhere for a leading entry, so the run must start at slot 1.
  • Madagascar Kartz ShippingFreighter owns 33 textures, its run is 33 long, and it draws slot 34. The run cannot start at slot 1, or slot 34 would have no texture at all.

One rule explains both, with no per-game constant:

Rule: Lay the run into the table in order, skipping slots. A skipped slot takes the next texture the run omits - a scenery texture, in GDF order - or stays empty when the track owns none to spare.

Madagascar's ShippingFreighter then starts at slot 2 because slot 1 is skipped and there is no spare texture for it, leaving slot 1 genuinely empty; Super Star Kartz's starts at slot 1 because it has nothing to skip. How many slots are skipped is forced - the run has to span the table, so it is exactly slots - runLength. Which slots are skipped is the only freedom, and for most tracks there is none of that either: when a track draws exactly as many slots as the run is long, the skips can only be the slots it never draws.

What the Data Does Not Record

  • Scenery billboards have no authored position. A level draws billboards - trees, plants - its .rdf never references. All seven of FoosaRocks' (FR_tree, FR_coco_tree, the *_spar plants) appear nowhere in main.rdf as archive references, though the track model draws four of them on hundreds of triangle corners each. Nothing says where in the table they load.
  • The table is not a permutation. Six textures are bound to two slots each: two in Madagascar's PlaneWreck, three in FoosaRocks (FR_fast_rock, FR_grass_tile, FR_fast_mud), and SS_Treewall01_A in both ShreksSwamp variants. The loader evidently binds one texture into more than one slot.
  • Forward and reverse variants are not mirrors. FoosaRocks and its reverse share one authored run entry for entry, but the two ShreksSwamp variants do not: SS_Trunk_01 is entry 8 of the reverse and entry 18 of the forward, and the reverse draws it in a spot the forward never uses.

How the Rule Was Checked

The order cannot be read back directly, since a TRK names a slot and never a file. Two independent measurements agree on it: the rule reproduces Super Star Kartz's known-good arrangement on 527 of 549 drawn slots, and every one of the 22 differences is a slot where the alternative had to choose between same-sized textures. Separately, authored UV rectangles land on whole multiples of their texture's dimensions, and the rule maximises the number of drawn slots where both axes do - 175 of 549 in Super Star Kartz and 64 of 333 in Madagascar Kartz, against 97 and 28 for a run laid down contiguously from slot 1.

Not Reverse-Engineered

  • Everything in the .rdf other than type-1 entries. The record dictionary resolves a property name as dictionary[1945 + key] and the string pool is readable, but the type codes and record grouping are not decoded.
  • The 60-byte record array. In Madagascar's main.rdf each track's run is shadowed by an array of 60-byte records at a fixed stride, one per run entry, whose second word points at that entry - exactly one per run entry for all 12 tracks. It looks like per-texture material state.
  • The .raf files entirely.

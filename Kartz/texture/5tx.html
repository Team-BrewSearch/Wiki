.5tx is the iStudio Nintendo DS texture container: a 16-byte NTTX header, an optional palette section and an image section. Seven pixel formats exist and six appear in the shipped data. The counts below are measured on the two Kartz games; every game on the engine uses the same reader.

Layout

+----------------------+   <-- 0x00
| NTTX header          |       16 bytes
+----------------------+   <-- 0x10
| PALT section         |       zero or more blocks
+----------------------+
| IMGE section         |       header + texel data
+----------------------+   <-- EOF

NTTX Header

OffsetSizeTypeDescription
0x004char[4]Magic "NTTX"

0x0C2u16TextureParam, 0x0010 on every shipped texture
0x0E2u16FormatHint, palette bank count plus one (below)
Note: A file with 0x0C and 0x0E zeroed decodes the same but the game rejects it and draws the texture as a solid fallback colour.

FormatHint

Each pixel format addresses a fixed number of palette entries at a time. The field is the palette's numColors divided by that number, rounded up, plus one. A DIRECT texture has no palette and stores 1.

banks     = (format == DIRECT) ? 0 : max(1, ceil(numColors / entriesPerBank[format]))
FormatHint = banks + 1

PALT Section

Repeats while the next four bytes read "PALT". In practice there is at most one.

OffsetSizeTypeDescription
+0x004char[4]Magic "PALT"
+0x044u32Section size, header included
+0x084u32numColors
+0x0C2 * nu16[]Palette entries, RGB555

IMGE Section

OffsetSizeTypeDescription
+0x004char[4]Magic "IMGE"
+0x044u32Section size, header included
+0x081u8format, see below
+0x091u8log2Width: padded width is 8 << log2Width
+0x0A1u8log2Height: padded height is 8 << log2Height
+0x0B1u8c0xp: non-zero makes palette index 0 transparent

+0x14varu8[]Texel data, sized to the padded dimensions
varvaru8[]Block data, format 5 only, half the size of the texel data

Rows are addressed by the padded width; the image is the top-left origWidth by origHeight region. Every shipped texture already has its original size equal to its padded size.

Formats 2, 3 and 4: Paletted

With iPx = x + y * paddedWidth, the index is (texel[iPx >> shift] >> ((iPx & mask) * bits)) & ((1 << bits) - 1) and the colour is palette[index]. Alpha is 0 only when index == 0 and c0xp is set; otherwise 255.

Format 1: A3I5

index = d & 0x1F, with no c0xp rule. Alpha is a3 = (d >> 5) & 7, widened to 5 bits as (a3 << 2) | (a3 >> 1) and then to 8 bits as (a5 * 510 + 31) / 62.

Format 6: A5I3

index = d & 0x7, with no c0xp rule. Alpha is a5 = (d >> 3) & 0x1F, widened to 8 bits the same way.

Format 7: DIRECT

Each texel is an RGB555 word. Alpha is 255 when bit 15 is set, otherwise 0.

Format 5: TEX4x4

4x4 pixel blocks. A u32 per block holds sixteen 2-bit indices; a parallel u16 per block, stored after the whole texel array, holds a palette address and a mode.

  • address = (cmp & 0x3FFF) << 1, always even
  • colors[0] = palette[address] and colors[1] = palette[address + 1], always opaque
  • cmp & 0xC000 == 0x0000: colors[2] = palette[address + 2], colors[3] transparent
  • 0x4000: colors[2] = Blend(c0, c1, 4), colors[3] transparent
  • 0x8000: colors[2] = palette[address + 2], colors[3] = palette[address + 3], both opaque
  • 0xC000: colors[2] = Blend(c0, c1, 3), colors[3] = Blend(c0, c1, 5), both opaque

Per pixel, j = (x & 3) + ((y & 3) << 2) and the index is (texel >> (2 * j)) & 3. Blend(a, b, f) is (a * (8 - f) + b * f + 4) / 8 per channel, passed through a 6-bit-to-8-bit table.

RGB555

Red is bits 0-4, green 5-9, blue 10-14, and bit 15 is unused in palettes. Expansion to 8 bits uses a rounding table, not bit replication: the 5-bit value 3 becomes 25, not the 24 that v << 3 | v >> 2 gives.

Magenta Colour Key

Cutout textures such as foliage, chain-link and glass do not use c0xp. They paint pure magenta, RGB (255, 0, 255), wherever the surface should be invisible; FF_tree03.5tx keys out 56.7% of its pixels that way.

Any pixel whose decoded colour is exactly (255, 0, 255) is fully transparent, in every format. This is a content convention: DS hardware has no colour key, only c0xp and per-format alpha.

Tracks Ignore c0xp

Six textures set c0xp: green_s in Super Star Kartz, and NY_water, WH_river and VO_lava_islands in Madagascar Kartz. None of them is meant to be keyed out, and honouring the flag punches holes through the track.

On hardware, colour-0 transparency is bit 29 of TEXIMAGE_PARAM, not a property of the file, and every textured group in both games' tracks leaves that bit clear. Track geometry draws palette index 0 opaque whatever its texture says.

Texture Binding

A chunk names its texture by slot. The slot resolves through the RDF slot table of the record that names the model; the first id in the slot's list that is a 5TX supplies the texture. The display list cannot help: its TEXIMAGE_PARAM is a constant 0x40000000 with no size, format or address, all of which the game fills in when it binds the texture.

In OmegaStudio

  • A blob is a texture when it is at least 16 bytes and starts with NTTX.
  • A PALT section counts only if its size is non-zero and fits the file. At most numColors entries are read, clamped to the bytes left.
  • The reader starts texels at IMGE +0x14 and sizes them from the format and padded size, not from the stored size words. log2Width and log2Height are clamped to 0..10. An image larger than its padded size, or larger than 16384 on a side, is rejected. An unknown format decodes as solid red.
  • A texture row honours c0xp. Track, scenery, car and character geometry ignores it, as the game does.
  • When no slot of a model resolves, every slot falls back to the one texture in the same folder whose name shares the most leading and trailing characters with the model's. A tie leaves the model untextured.
  • Replacing from a PNG re-encodes in the original format, or PLTT256 for an unknown one. The image is padded to a power of two (at least 8) by repeating its edge pixels, and the palette is built by median cut at the format's full size.
  • Pixels with alpha below 128 take palette index 0, set to magenta, in PLTT4, PLTT16 and PLTT256. A3I5 and A5I3 quantise alpha to their 3 or 5 bits, and DIRECT sets bit 15 for alpha of 128 or more.
  • The writer always emits a PALT section, an empty one for DIRECT, and carries TextureParam, FormatHint and c0xp through from the original.

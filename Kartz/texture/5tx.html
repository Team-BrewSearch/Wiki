.5tx is the iStudio NDS texture container: a 16-byte NTTX header, an optional palette section, and an image section. Seven pixel formats exist; six appear in the shipped data.

File Layout

+----------------------+   <-- offset 0
| NTTX header          |       16 bytes
+----------------------+
| PALT section         |       zero or more consecutive blocks
+----------------------+
| IMGE section         |       header + texel data
+----------------------+   <-- EOF

NTTX Header

OffsetSizeTypeDescription
0x004char[4]Magic "NTTX"
0x042u160xFEFF, byte-order mark
0x062u160x0100, version
0x084u32Total file size
0x0C2u16textureParam - 0x0010 for every shipped texture but one
0x0E2u16formatHint - 0x0001 for format 7, 0x0002 for the paletted, A3I5 and A5I3 formats, rarer values for format 5
Note: The fields at 0x0C and 0x0E are inert when reading a texture and load-bearing when writing one. A file that zeroes them decodes identically but is rejected by the game, which draws the affected texture as a solid fallback colour.

PALT Section

Repeats while the next four bytes read "PALT"; in practice there is at most one.

OffsetSizeTypeDescription
+0x004char[4]Magic "PALT"
+0x044u32Section size, including magic, size, count and data
+0x084u32numColors
+0x0C2 * nu16[]Palette entries, RGB555

IMGE Section

OffsetSizeTypeDescription
+0x004char[4]Magic "IMGE"
+0x044u32Section size
+0x081u8format, see below
+0x091u8log2Width - padded width is 8 << log2Width
+0x0A1u8log2Height - padded height is 8 << log2Height
+0x0B1u8c0xp - nonzero renders palette index 0 fully transparent
+0x0C2u16origWidth
+0x0E2u16origHeight
+0x104u32Combined texel payload size
+0x14varu8[]Texel data, sized to the padded dimensions
varvaru8[]Block mode data, format 5 only, exactly half the texel array's size

Rows are addressed by the padded width, then the leftmost origWidth columns and first origHeight rows are kept. Every shipped texture already has origWidth and origHeight equal to its padded size, so the crop is a no-op there, but it is required for correctness in general.

The byte at +0x09 is log2(width / 8) with zero exceptions across all 1101 shipped textures; it is not a flags field.

Formats 2, 3 and 4 - paletted

With iPx = x + y * paddedWidth, the index is (texel[iPx >> shift] >> ((iPx & mask) * bits)) & ((1 << bits) - 1). Colour is palette[index]. Alpha is 0 only when index == 0 and c0xp is set, otherwise 255.

Format 1 - A3I5

index = d & 0x1F, no c0xp rule. Alpha comes from a3 = (d >> 5) & 7, expanded to 5 bits as (a3 << 2) | (a3 >> 1) and then to 8 bits as (a5 * 510 + 31) / 62.

Format 6 - A5I3

index = d & 0x7, no c0xp rule. Alpha is a5 = (d >> 3) & 0x1F, expanded to 8 bits the same way.

Format 7 - DIRECT

Each texel is a raw RGB555 word. Alpha is 255 when bit 15 is set, otherwise 0.

Format 5 - TEX4x4

4x4 pixel blocks. A u32 per block holds sixteen 2-bit pixel indices; a parallel u16 per block, stored after the whole texel array, carries a palette base address and a mode.

  • address = (cmp & 0x3FFF) << 1, always even
  • colors[0] = palette[address] and colors[1] = palette[address + 1], always opaque
  • cmp & 0xC000 == 0x0000: colors[2] = palette[address + 2], colors[3] transparent
  • 0x4000: colors[2] = Blend(c0, c1, 4/8), colors[3] transparent
  • 0x8000: colors[2] = palette[address + 2], colors[3] = palette[address + 3], both opaque
  • 0xC000: colors[2] = Blend(c0, c1, 3/8), colors[3] = Blend(c0, c1, 5/8), both opaque

Per pixel, j = (x & 3) + ((y & 3) << 2) and pixelIndex = (texel >> (2 * j)) & 0x3. Blend(a, b, f) is round((a * (8 - f) + b * f) / 8) per channel.

RGB555

Colours are 15-bit: R in bits 0-4, G in bits 5-9, B in bits 10-14, bit 15 unused. Conversion to 8-bit uses rounding tables rather than bit replication - raw 5-bit value 3 becomes 25, not the 24 a naive << 3 | >> 5 produces.

The Magenta Colorkey

Transparency for foliage, chain-link, glass and similar cutout textures is not c0xp. Those textures paint pure magenta, RGB (255, 0, 255), into the area that should be invisible: FF_tree03.5tx uses it for 56.7% of its pixels and FF_chain.5tx for 24.2%, against 6.4% for an ordinarily opaque texture where it is only an unused palette slot.

Any pixel whose decoded RGB is exactly (255, 0, 255) is fully transparent, in every format. This is a content convention layered on top of the hardware format - real DS hardware has no colorkey, only c0xp and per-format alpha.

c0xp Is Set on Six Textures, and Track Geometry Ignores It

Six textures across both games set c0xp: green_s in Super Star Kartz, and NY_water, WH_river and VO_lava_islands - each in a track and its _Reverse variant - in Madagascar Kartz. Nothing is keyed out in any of them. Honouring the flag punches holes through geometry: NY_water loses 20.6% of its pixels, and its palette entry 0 is a water blue no different from entries 1 to 3, while WH_river's entries 0 and 1 are byte-identical.

On hardware, colour-0 transparency is bit 29 of TEXIMAGE_PARAM, not a property of the file. All 9145 textured groups across both games' tracks - 4792 in Super Star Kartz, 4353 in Madagascar Kartz - carry that bit clear, so a track draws palette index 0 opaque whatever its texture file says.

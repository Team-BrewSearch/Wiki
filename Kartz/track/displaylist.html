A TRK chunk's payload is a Nintendo DS GX command stream, packed four opcodes per 32-bit word. Each opcode then consumes zero or more full parameter words from the same shared word stream before the next opcode is read. A group of fewer than four opcodes at the end of a chunk is padded with 0x00 bytes - command 0 takes no parameters and does nothing.

Vertex Positions

Of the six GX vertex-position opcodes, track data uses exactly two: VTX_16 for every genuinely new position, and VTX_DIFF - always with a parameter of literally 0 - for a position identical to the previous vertex's. No VTX_16 ever repeats the preceding position.

Duplicates are common because a mode-0 block emits three independent vertices per triangle, so a triangle reusing a vertex from the one before it restates that position. VTX_16's raw range is only about plus or minus 8 units, which is why one translate and scale pair is emitted per chunk.

Group Shape

  • A chunk opens with MTX_PUSH, then MTX_TRANS, then MTX_SCALE. The order matters: on hardware both matrix opcodes multiply the current matrix, so MTX_SCALE first would give scale * translate + scale * v instead of translate + scale * v.
  • Every TEXIMAGE_PARAM is immediately followed by PLTT_BASE and then a baseline white COLOR of 0x7FFF, all before BEGIN_VTXS.
  • COLOR persists across an entire texture group - the whole run of blocks under one TEXIMAGE_PARAM - and is re-emitted only when it changes or when a group opens.
  • TEXCOORD resets at every BEGIN_VTXS: a fresh block's first vertex emits it explicitly even when it matches the previous block's last one, and only vertices within the same block skip a repeat.
  • NORMAL never appears. Track geometry is vertex-colour shaded only.
  • Every non-empty chunk ends with exactly one MTX_POP immediately after its final END_VTXS, then whatever no-ops complete the final packed word.

END_VTXS Padding

When END_VTXS lands as the fourth opcode of its packed word, a whole extra padding word of four no-ops follows before the next real opcode, even though the group is already word-aligned. When it lands in slot 0, 1 or 2, no padding follows at all. The rule keys only on which slot the opcode happened to land in.

Note: Every non-empty chunk contains exactly one MTX_PUSH and pops exactly one level. The DS position and direction matrix stack is only 31 levels deep and raises a GXSTAT overflow bit, so a chunk that pushes without popping is a load-time hardware fault rather than a cosmetic difference.

Primitive Modes and Strips

Real chunks use mode 2 triangle strips extensively, not just mode 0 separate triangles: a strip of N triangles costs N + 2 vertices instead of 3N. No mode-2 block anywhere has fewer than 4 vertices.

Three constraints describe how strips are built:

  1. Sequential. A strip is only ever extended with the very next triangle.
  2. Never rotated. A strip continues only when the candidate triangle is already written as (x, y, z) for the pair the strip needs.
  3. The fallback is final. Once a triangle cannot open a strip, every remaining triangle in the group goes out as one list.

Block layout is an authoring choice, not a property of the geometry: mode-0 blocks routinely hold triangles that would chain into perfectly valid strips, and a group opening with a two-triangle strip may then fall back or ship as a pure list with nothing in the geometry to separate the two cases.

Group Boundaries

Every group either opens its chunk or follows a different texture, with exactly one exception across both games - chunk 0 of Madagascar's PlaneWreck reopens the same texture. A new TEXIMAGE_PARAM is very nearly, but not quite, a reliable signal for a texture change.

Scale

MTX_SCALE is always a clean power of two - 2, 4, 8, 16, 32, 64 and 256 are observed - but not the smallest one that fits the chunk's own geometry. It reflects the level tool's nominal cell size for that chunk index, which the geometry does not record.

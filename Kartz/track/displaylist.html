A TRK chunk's payload is a Nintendo DS GX command stream, packed four opcodes per 32-bit word. Each opcode then takes zero or more whole parameter words from the same stream before the next opcode is read. A final group of fewer than four opcodes is padded with 0x00, which takes no parameters and does nothing. ZON, CAR and AMD chunks use the same stream. The notes below are measured on the two Kartz games.

No other opcode appears in Kartz track data, and MTX_RESTORE appears only in character models.

Chunk Shape

  • A chunk opens with MTX_PUSH, MTX_TRANS, MTX_SCALE, in that order. Both matrix opcodes multiply the current matrix, so scaling first would give scale * translate + scale * v instead of translate + scale * v.
  • Every TEXIMAGE_PARAM is followed by PLTT_BASE and then a baseline white COLOR of 0x7FFF, all before BEGIN_VTXS.
  • COLOR holds across a whole texture group, the run of blocks under one TEXIMAGE_PARAM, and is re-sent only when it changes or a group opens.
  • TEXCOORD marks only the next vertex as textured.
  • NORMAL never appears. Track geometry is shaded by vertex colour only.
  • Every non-empty chunk ends with one MTX_POP right after its last END_VTXS, then whatever no-ops complete the word.
Note: Every non-empty chunk pushes once and pops once. The DS position and direction matrix stack is 31 levels deep and raises a GXSTAT overflow bit, so a chunk that pushes without popping is a hardware fault, not a cosmetic difference.

END_VTXS Padding

When END_VTXS lands as the fourth opcode of its word, a whole word of four no-ops follows before the next real opcode, even though the stream is already aligned. In slots 0, 1 and 2 no padding follows. The rule depends only on the slot.

Empty chunks are rare, 8 of Super Star Kartz's 3996, and no non-empty display list emits zero vertices. Untextured geometry is always the shape above, never a reference to slot 0.

Every group either opens its chunk or follows a different texture, with one exception across both games: chunk 0 of Madagascar's PlaneWreck reopens the same texture. A new TEXIMAGE_PARAM is nearly, but not quite, a reliable texture-change signal.

Vertices

Of the six GX vertex opcodes, tracks use two: VTX_16 for every new position, and VTX_DIFF with a parameter of exactly 0 for a position equal to the previous vertex. No VTX_16 repeats the preceding position. Repeats are common because a mode-0 block sends three vertices per triangle, so a triangle that reuses a corner restates it.

VTX_16 reaches only about ±8 units, which is why each chunk carries its own translate and scale. MTX_SCALE is always a power of two (2, 4, 8, 16, 32, 64 and 256 occur) but not always the smallest that fits: it follows the level tool's cell size for that chunk index, which the geometry does not record.

Strips

Real chunks use mode 2 strips heavily, not just mode 0 triangles: a strip of N triangles costs N + 2 vertices instead of 3N. No mode-2 block has fewer than 4 vertices. Three rules describe how strips are built:

  1. Sequential. A strip only grows by the very next triangle.
  2. Never rotated. A strip continues only when the next triangle is already written as (x, y, z) for the pair the strip needs.
  3. The fallback is final. Once a triangle cannot open a strip, every remaining triangle in the group goes out as one list.

Block layout is an authoring choice, not a property of the geometry. Mode-0 blocks routinely hold triangles that would chain into valid strips, and nothing in the geometry tells a two-triangle strip followed by a list apart from a pure list.

In OmegaStudio

Reading

Every command is given a parameter count and consumes that many words, whether or not it is applied:

  • MTX_PUSH resets the reader's scale and translation; the hardware stack itself is not modelled. A vertex is placed at v * scale + translate.
  • Position updates: VTX_16, VTX_XY, VTX_XZ and VTX_YZ take signed 16-bit values divided by 4096; VTX_10 takes signed 10-bit values divided by 64; VTX_DIFF adds signed 10-bit values divided by 4096.
  • COLOR expands each 5-bit channel by bit replication. TEXCOORD divides by 16 and marks only the next vertex as textured.
  • TEXIMAGE_PARAM switches texture by matching the byte offset of its parameter word, counted from the start of the display list, against the chunk's references.
  • Quads split as (0, 1, 2) and (0, 2, 3); strips alternate winding; quad strips emit (0, 1, 3) and (0, 3, 2).

Writing

The track writer emits exactly the chunk shape above: push, translate, scale, then per group TEXIMAGE_PARAM, PLTT_BASE and baseline COLOR, blocks, and a final MTX_POP, with the END_VTXS padding rule. It re-sends COLOR only when it changes and TEXCOORD when it changes or a block opens, unless the imported glTF records which vertices carried one, and writes VTX_DIFF 0 for a repeated position. A glTF exported by OmegaStudio carries each primitive's block list, texcoord flags and group breaks in its extras, so an unedited track rebuilds with the blocks it came with; otherwise triangles are grouped by texture and chained into strips under the three rules above.

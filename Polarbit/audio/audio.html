Polarbit games use two audio formats: PSND sound blocks and PMOD tracker modules (CNK3D and KKR only). CNK2 uses streamed PCM for music; the others use PMOD for music.

PSND Sound

OffsetSizeTypeDescription
0x004char[4]Magic PSND
0x044u32Size of what follows
0x082u16A = number of header bytes after this field; sample data starts at offset 10 + A
0x0A2u16Flags
0x0C2u16Sample rate, Hz
0x0E-Optional fields, in this order, when their flag bit is set:
BitField
0x001u8 channels (1 if absent)
0x002u8 bits per sample, 8 or 16; presence means PCM
0x004u16 default volume, 0-256 (absent = full)
0x008u32 loop start, u32 loop end, in samples
0x010u8 loop type: 2 = ping-pong (absent = forward)
0x200u16 unknown (80 to 180, always a multiple of 10)
0x400i16 finetune, 1/128 semitone
0x800i8 relative note, semitones

No other flag bits occur. A sound without the bits field is IMA ADPCM with no header fields of its own: the high nibble is decoded first and both predictor and step index start at 0.

PMOD Music Modules

+0x00  4     "PMOD"
+0x04  u32   size - 8
+0x08  u32   30 (header length)
+0x0C  u16   1 (version)
+0x0E  u16   4096 (unknown)
+0x10  u8    initial speed (CNK3D 2, KKR 3/4/6)
+0x11  u8    BPM
+0x12  u16   song length (order count)
+0x14  u16   restart position
+0x16  u16   pattern count
+0x18  u16   rows per pattern, or 0 for per-pattern row counts (KKR)
+0x1A  u16   channels (CNK3D 32, KKR 16, one module 4)
+0x1C  u16   256 (unknown)
+0x1E  u16   sample count
+0x20  u16   instrument count
+0x22  u16   27 (unknown)
+0x24  u16   0
+0x26  u32   54784 (unknown)
+0x28  ...   zlib stream (level 9) holding the module body

The inflated body is laid out as: order list, per-pattern row counts (when rows field is 0), patterns, embedded PSND samples, and instruments. Each instrument has a keyframe length, a 96-entry keymap, envelope count and per-envelope point data.

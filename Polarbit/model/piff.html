PIFF is an IFF-style chunk container used for models (.pof) and tracks (.trk) in CNK2, CNK3D and Krazy Kart Racing. The two KKR track files use the CNK3D record layouts throughout.

Container

+0x00  4    "PIFF"
+0x04  u32  file size - 8
+0x08  4    file type: "3DOB" (object/model) or "SCEN" (scene/track)
+0x0C  ...  chunks: { 4-byte id, u32 size, size bytes of data }

Chunks are not padded, so odd sizes such as MTRL's 25 bytes are normal. A FORM chunk is a group: its data starts with a 4-byte group type and the rest is a list of child chunks.

3DOB Models

Top-level chunks, in file order: HEAD, TEXL, then MTRL + APPR (newer models) or MATL / MAT2 (older ones), MESH, NORM, TXUV, COLR, one POLY per primitive group, ID, then optional FORM:SKIN, FORM:ANIM and FORM:LOD groups.

Materials

u32  index count

ID

Four ASCII characters: LOD1, LOD2, TNT , lod0. Marks which LOD or variant a standalone file is.

Skinning: FORM:SKIN

JNTS

u32  index count NI
u32  weight count NW
u32  copy count NC
u16  vertex index [NI]
     zero padding to 4 bytes, only if NW > 0
i32  weight [NW]            (fixed, 0..1)
{ u16 source, u16 dest } [NC]

SKEL

u32  bone count
per bone (40 bytes):
  u32  bone id: a 4CC name ("root", "hip ", "neck", "head", "back", "base", "nose") or a small integer
  u32  parent id (-1 for root), referring to the parent's id, not position
  i32  rigid vertex count
  i32  weighted vertex count
  i32  first rigid entry in JNTS index list (-1 if none)
  i32  first weighted entry in JNTS index list (-1 if none)
  i32  first weight in JNTS weight list (-1 if none)
  fixed x, y, z: bone pivot in model space

A bone's rigid vertices get weight 1. Its weighted vertices take weights from the weight list starting at its own offset. The copy list handles UV seams: after skinning, vertex dest is a copy of vertex source. In all skins, rigid, weighted and copied vertices together cover every vertex exactly once, and every vertex's weights add up to 1 within 0.03.

KEYF

u32 key count NK
u32  reserved (zero)
u32  reserved (zero)
i32  time[NK]   (milliseconds)

Times rise steadily within a file and can start below zero.

ARNG

u32  count
per clip: {4CC name, u32 first key, u32 last key}

Levels of Detail: FORM:LOD

LODI

u32   count
per entry: fixed switch distance, u32 level

Level 0 is the top-level mesh. Each further level is a FORM:MESH holding MSHD (10 i32 matching HEAD[1..9]), MESH, TXUV, POLY, and its own FORM:SKIN.

SCEN Tracks

Track chunks in order: VERS (CNK2 only), VERT, TCOR, COLR, TXTR, MATL, INDS, CHNK, CHAN, POSI, CAMS (CNK3D only), PICK, EMIT (CNK2), LINE, CELL, PORT, FORM:BSPS.

Layout Chunks

ChunkLayout
VERS4 bytes: 03 01 01 00 (CNK2 only)
VERTu32 count, then i16 x, y, z per vertex, in 1/64 units (relative to grid cell)
TCORu32 count, then i16 u, v per vertex, in 1/256 units
COLRu32 1, u32 count, then u16 per colour in ARGB4444
TXTRu32 count, then texture names (see below)
INDSu32 byte length, then index data (8- or 16-bit per chunk)
CHNKu32 count, then one draw-chunk record per chunk
VOFFu32 count, then 20-byte records per grid cell

CNK2 TXTR entries are {u8 flag, u8 length, chars}; CNK3D-layout entries are {u8 length, chars} with entry 0 as empty name.

CHNK Record

VariantSizeFields
CNK218 bytesu16 material, u16 vertex base, u16 1, u16 texcoord base, u16 colour base, u16 index size (1 or 2), u16 index count, u16 index offset (2-byte units), u16 0
CNK3D layout14 bytesu16 material, u16 vertex base, u16 texcoord base, u16 colour base, u16 index size, u16 index count, u16 index offset

VOFF Grid Cell (20 bytes)

fixed x, y, z  (cell origin)
u16 first, u16 count   run A
u16 first, u16 count   run B

Cells are 100 x 100 world units. World position = cell origin + VERT / 64.

Gameplay Data

ChunkContents
CHANAnimated objects and cameras: flags (bit 0 pos, 1 rot, 2 scale), key count, param, then values per key
POSINamed positions: 32 bytes each ({4CC tag, u32 kind, fixed position[3], fixed direction[3]})
CAMSCNK3D-layout cameras (same 32-byte record)
PICKPick-ups and crates: type, subtype, fixed position[3], fixed direction[3]
EMITCNK2 particle emitters: type, position[3], direction[3], kind, parameter
LINE36-byte lines: LAP0–LAP3, CHK*, JMP*, WW0–WW3, DRV*, CAM1
CELLCell-and-portal visibility: 16 bytes per cell
PORT152 bytes per portal: target cell, vertex count (3–12), fixed vertices[12][3]

BSPC: Collision and Quads

FORM:BSPS holds BSPC (quad count) and QUAD groups. Each QUAD has:

  • COLL: polygon groups. Each group is u16 polygon count, then per polygon u16 (material << 10 | vertex count) + vertex indices into VERT. Material numbers index the game's material-response list.
  • OBJS: placed objects. u32 count, then per object fixed position[3], fixed rotation[3], fixed scale[3], u16 type + type-dependent tail.
  • OLST, BORD, RECT: quad-tree spatial partitioning with polygon strips.

PIFF is an IFF-style chunk container for models (.pof, type 3DOB) and tracks (.trk, type SCEN) in CNK2, CNK3D and Krazy Kart Racing. Krazy Kart Racing's two tracks use the CNK3D record layouts throughout.

Container

OffsetSizeTypeDescription
0x004char[4]Magic "PIFF"
0x044u32File size minus 8
0x084char[4]File type: 3DOB (model) or SCEN (track)
0x0Cvarchunk[]Chunks: 4-byte id, u32 size, then size bytes

Chunks are not padded, so odd sizes such as MTRL's 25 bytes are normal. A FORM chunk is a group: its data starts with a 4-byte group type, followed by child chunks. Below, FORM:SKIN means a FORM of type SKIN.

3DOB Models

Top-level chunks in file order: HEAD, TEXL, then MTRL and APPR (newer models) or MATL or MAT2 (older ones), MESH, NORM, TXUV, COLR, one POLY per primitive group, ID , then optional FORM:SKIN, FORM:ANIM and FORM:LOD .

HEAD

76 bytes (19 i32) on models with MTRL and APPR, 72 bytes (18 i32) on the rest.

ID

Four ASCII characters, such as LOD1, LOD2, TNT or lod0, marking which level of detail or variant a standalone file is.

Skinning: FORM:SKIN

JNTS

SizeTypeDescription
4u32Index count NI
4u32Weight count NW
4u32Copy count NC
2 * NIu16[NI]Vertex indices, zero-padded to 4 bytes when NW > 0
4 * NWfixed[NW]Weights, 0 to 1
4 * NC{u16 source, u16 dest}[NC]Seam copies

SKEL

u32 bone count, then 40 bytes per bone:

OffsetSizeTypeDescription
+0x004u32Bone id: a 4CC name (root, hip , neck, head, back, base, nose) or a small integer
+0x044u32Parent's id, not its position; -1 for the root
+0x084i32Rigid vertex count
+0x0C4i32Weighted vertex count
+0x104i32First rigid entry in the JNTS index list, -1 if none
+0x144i32First weighted entry in the JNTS index list, -1 if none
+0x184i32First weight in the JNTS weight list, -1 if none
+0x1C12fixed[3]Bone pivot in model space

A bone's rigid vertices take weight 1; its weighted vertices take weights from the weight list starting at its own offset. The copy list handles UV seams: after skinning, vertex dest copies vertex source. In every skin, rigid, weighted and copied vertices together cover each vertex exactly once, and every vertex's weights sum to 1 within 0.03.

Animation: FORM:ANIM

ChunkLayout
KEYFu32 key count NK, two reserved zero words, then i32 time[NK] in milliseconds. Times rise through the file and can start below zero
ARNGu32 clip count, then per clip {4CC name, u32 first key, u32 last key}
BANIu32 NT, the number of bones with translation keys (0 or the bone count), then fixed translation[NK][NT][3], then fixed rotation[NK][bones][4] as quaternions w, x, y, z
XFRMu32 2, then fixed x, y, z scale per key

Clip names seen: ACCL, ACT0, ATCK, BNDP, BOOM, BREK, DEAD, HAPY, HIT1, IDLE, LBCK, LOSE, NULL, SAAD, SAD1, SPWN, STAD, STLS, TURN, WIN1, WIN2.

Levels of Detail: FORM:LOD

LODI holds a u32 count, then per entry a fixed switch distance and a u32 level. Level 0 is the top-level mesh. Each further level is a FORM:MESH holding MSHD (10 i32 matching HEAD[1..9]), MESH, TXUV, POLY and its own FORM:SKIN.

SCEN Tracks

Chunks in order: VERS (CNK2 only), VERT, TCOR, COLR, TXTR, MATL, INDS, CHNK, CHAN, POSI, CAMS (CNK3D only), PICK, EMIT (CNK2), LINE, CELL, PORT, FORM:BSPS, plus VOFF. A VERS chunk marks the CNK2 layout.

Geometry

ChunkLayout
VERS4 bytes, 03 01 01 00
VERTu32 count, then i16 x, y, z per vertex in 1/64 units, relative to its grid cell
TCORu32 count, then i16 u, v per vertex in 1/256 units
COLRu32 1, u32 count, then a u16 ARGB4444 colour each
TXTRu32 count, then names: {u8 flag, u8 length, chars} in CNK2, {u8 length, chars} in the CNK3D layout, where entry 0 is an empty name
MATLu32 count, then 14-byte records (CNK2: flags at +0, texture at +6) or 8-byte records (CNK3D layout: texture at +0, flags at +2). Flag bit 0 means textured, bit 4 (0x10) vertex-coloured
INDSu32 byte length, then index data, 8 or 16 bits per chunk
CHNKu32 count, then one draw chunk record each
VOFFu32 count, then a 20-byte record per grid cell

CHNK Record

LayoutSizeFields (all u16)
CNK218 bytesmaterial, vertex base, 1, texcoord base, colour base, index size (1 or 2), index count, index offset (2-byte units), 0
CNK3D14 bytesmaterial, vertex base, texcoord base, colour base, index size, index count, index offset

A chunk draws a triangle list. Each index is added to the chunk's vertex, texcoord and colour bases.

VOFF Grid Cell (20 bytes)

OffsetSizeTypeDescription
+0x0012fixed[3]Cell origin
+0x0C4u16[2]First vertex and count, run A
+0x104u16[2]First vertex and count, run B

Cells are 100 by 100 world units. A vertex's world position is its cell origin plus VERT / 64.

Gameplay Data

ChunkContents

PICKPick-ups and crates: type, subtype, fixed position[3], fixed direction[3]

CELLCell-and-portal visibility, 16 bytes per cell
PORT152 bytes per portal: target cell, vertex count (3 to 12), fixed vertices[12][3]

FORM:BSPS: Collision and Quads

FORM:BSPS holds BSPC (the quad count) and FORM:QUAD groups. Each quad has:

  • COLL: polygon groups. Each is a u16 polygon count, then per polygon u16 (material << 10 | vertex count) and vertex indices into VERT. Materials index the game's material response list.
  • OBJS: placed objects. A u32 count, then per object fixed position[3], rotation[3] and scale[3], a u16 type and a type-dependent tail.
  • OLST, BORD, RECT: quad-tree spatial partitioning with polygon strips.

In OmegaStudio

Reading

  • The size word must equal the file size minus 8, every chunk must fit inside its parent, and the chunk list must end exactly at the parent's end.
  • 3DOB: HEAD is 72 or 76 bytes; NORM, TXUV and COLR must match the MESH vertex count; POLY uses mode 4 or 5 and index type 5121 or 5123, its size matches its count, and every index is in range. Degenerate strip triangles are dropped.
  • Skins: JNTS and SKEL sizes must match their counts, every index and weight lookup must be in range, and every parent id must name a bone in the skeleton. Each vertex keeps its four heaviest influences, normalised.
  • Clips play at 30 fps, timed from KEYF milliseconds. Bones rotate about their pivots, and BANI translations add to the pivot offset.
  • SCEN: VERT, TCOR and COLR sizes must match their counts; MATL, CHNK and VOFF too; every CHNK record must name a material and stay inside INDS. Vertex colours are used only when a material sets bit 4. The Properties pane counts positions, cameras, pick-ups, emitters, lines and collision quads.

Replacing a Model from glTF

  • Every glTF mesh is merged into the model's single mesh, up to 65,535 vertices. Materials map to appearances by texture name; surplus materials draw with the last one.
  • MESH, NORM, TXUV, COLR and POLY are rewritten (POLY as 16-bit triangle lists) and HEAD updated to match. Every other chunk is copied, FORM:ANIM included. Lower levels of detail are dropped.
  • On a skinned model, joints bind to bones by name (ignoring case and a _n suffix) or by position in the list. A vertex with one bone at 99.9% or more becomes rigid; others are weighted. Unskinned vertices follow the root. No seam copies are written.
  • PIFF tracks cannot be replaced from glTF.

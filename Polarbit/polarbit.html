Reference for the file formats of Polarbit's mobile racing engine, as found in seven .vfs archives across five games. The engine ships in Crash Bandicoot Nitro Kart 2, Crash Bandicoot Nitro Kart 3D, Krazy Kart Racing, Reckless Getaway and Raging Thunder 2.

File Formats

    Engine Generations

    All five games run on Polarbit's mobile engine and share one container format. Two generations differ in their 3D content:

    CNK2, CNK3D, KKR
    Use PIFF models and tracks, PNG or PVR textures, and PSND/PMOD audio. Store only name hashes — file names are recovered by hashing path-like strings found in the data.
    Getaway, RT2
    Replace PIFF with the PXC scene graph, add texture-atlas "plates", GLSL shaders, and new string tables (FCOL). Store file names inside the archive.

    Conventions

    All integers are little-endian, with one exception noted on the plates page. "Fixed" means a signed 32-bit 16.16 fixed-point number (divide by 65536). Several headers use OpenGL ES constants directly: 4 = GL_TRIANGLES, 5 = GL_TRIANGLE_STRIP, 5121 = GL_UNSIGNED_BYTE, 5123 = GL_UNSIGNED_SHORT, 5132 = GL_FIXED.

    Content Overview

    Assets are addressed by path hash inside FUFS containers, then unwrapped through zero, one or two zlib compression layers. Textures are either PNG (direct) or PVR (PowerVR). Models are PIFF for the older games and PXC for the 2011 games. Audio is PSND sound blocks or PMOD tracker modules. Strings live in LANG or FCOL tables, or as CSV/HXX sources in Getaway.

    Verified: A companion tool (cnk2tool.py) enforces every byte of every file: containers rebuild byte-for-byte, all 2,511 entries unwrap through compression layers, all 1,546 zlib streams re-compress to the exact original bytes, all 649 stored file names hash to their table entries, and every editable entry round-trips through conversion and back.

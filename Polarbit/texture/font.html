PFNT is Polarbit's bitmap font format: one atlas per file, built from a 12-byte fixed header, a glyph record for every character in the range, and a palette followed by the pixel data. The pixel-format byte selects one of the per-game layouts below.

File Layout

0    4      "PFNT"
4    u16    12 (size of the fixed header that follows)
6    u8     0 in every font (meaning unknown)
7    u8     Widest glyph, pixels
8    u8     Ascent / baseline (smaller than the height)
9    u8     Line height = atlas height
10   u16    0 in every font (meaning unknown)
12   u16    First character code
14   u16    Last character code
16   u16    Glyph count G
18   u16[G] Character codes (UCS-2)
..   G x 4  Glyph records { u16 x in atlas, u8 0, u8 width }
..   u8     Pixel format: 8 = RGBA8888, 3 = 8 bits per pixel
..   u8     Flags
..   u16    Palette entry count P
..   u16    Atlas width W
..   u16    Atlas height H
..   u32    0
..   5      Only if flags & 0x80: { u8 1, u32 0 } (colour-key style record)
..   P x 3  RGB palette
..   ...    W x H pixels, top row first

Glyphs sit side by side in one horizontal strip; glyph i spans x .. x+width at full height.

Pixel Formats

CNK2 (9) and KKR (5) fonts: RGBA8888 in R, G, B, A byte order, with flags 0x00 or 0x82.

CNK3D and RT2 fonts: format 3 (8 bits per pixel):

  • flags 0x38 and 0x78, no palette: one byte per pixel of coverage (alpha).
  • flags 0x18 (RT2) and 0x58, 256-entry palette: one byte per pixel, a palette index.
  • flags 0xDE, 35-entry palette: every byte is either below 35 or 224 and up. Read as 3 bits of alpha over 5 bits of palette index (alpha = v >> 5, index = v & 31), matching Nintendo DS-style A3I5 textures. Rests on a single sample.

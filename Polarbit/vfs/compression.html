An entry payload is either stored raw or wrapped in one or two zlib layers. PLZP is a simple wrapper; PIFF and PXC files are often stored as a bare zlib stream.

PLZP

0   4   magic "PLZP"
4   4   uncompressed size
8   4   compressed size (= entry size - 12)
12  ..  zlib stream

The zlib header is always 78 DA. PLZP wraps textures, sounds, fonts, plates, some PNG and XML files, and the large track and scene files. Krazy Kart Racing's five fonts are PLZP inside PLZP.

Bare zlib

PIFF and PXC files are often stored as a plain zlib stream. CNK2 uses 78 9C (level 6). The other games use 78 9C and 78 DA. Seventeen PIFF files and 56 of the 61 PXC files are double-wrapped: a PLZP whose payload is itself a bare zlib stream.

Detect a bare zlib stream by a first byte of 0x78 and (b0*256 + b1) % 31 == 0, then confirm it inflates with no trailing data. No raw payload in any archive starts that way by accident.

Exact Compression Parameters

Getting every stream to re-compress bit for bit required recovering how the original tools called zlib:

  • Level comes from the FLEVEL bits of the zlib header: 78 9C means level 6, 78 DA means level 9.
  • memLevel is 9 (not zlib's default of 8). It matters for large streams.
  • windowBits 15, default strategy, with one exception below.
  • The model, track and font writers fed zlib one file section at a time and called deflate(Z_FULL_FLUSH) at section boundaries. Each flush shows up as an empty stored block (00 00 FF FF).
  • The original zlib was version 1.2.4 or older. From 1.2.5.1 on, a full flush rewinds the sliding window to position 0, which makes the first bytes after the flush unmatchable. Old zlib kept the window position and only cleared the hash table.
  • Sometimes an empty fixed-Huffman block (10 bits) appears just before the empty stored block. That is old zlib behaviour when the 8 KB output buffer fills during the flush: the second deflate call emitted an extra empty block. It happens when the final data block before the flush is larger than about 8,192 bytes.
  • The Raging Thunder 2 font (font02.fnt) compressed its palette section with Z_FILTERED and switched back to the default strategy for the pixels. It is the only stream that needs this.
Flush placement: For CNK2 models, a flush happens before any chunk whose total size is at least about 1 KB (1,032 bytes including the 8-byte chunk header), after enough bytes have accumulated (about 4.1 KB), and at the end of some FORM groups. This reproduces the flush layout of 95 of 110 CNK2 model and track streams. The game does not care where flushes are — any valid zlib stream works, so edited files can be compressed normally.

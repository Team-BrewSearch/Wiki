An entry payload is stored raw or wrapped in one or two zlib layers. PLZP is a small wrapper with sizes; PIFF and PXC files are often a bare zlib stream instead, or both.

PLZP

OffsetSizeTypeDescription
0x004char[4]Magic "PLZP"
0x044u32Uncompressed size
0x084u32Compressed size, the entry size minus 12
0x0Cvar-zlib stream, always 78 DA

PLZP wraps textures, sounds, fonts, plates, some PNG and XML files, and the large track and scene files. Krazy Kart Racing's five fonts are PLZP inside PLZP.

Bare zlib

PIFF and PXC files are often stored as a plain zlib stream: 78 9C (level 6) in CNK2, 78 9C or 78 DA in the other games. Seventeen PIFF files and 56 of the 61 PXC files are double-wrapped, a PLZP whose payload is itself a bare zlib stream.

A bare stream starts with 0x78 and satisfies (b0 * 256 + b1) % 31 == 0, and must then inflate cleanly. No raw payload in any archive starts that way by accident.

Original Compressor Settings

These are how the original tools called zlib, recovered by re-compressing every stream until it matched bit for bit. The game does not depend on them: it accepts any valid zlib stream, so an edited file can be compressed normally.

  • Level follows the FLEVEL bits of the zlib header: 78 9C is level 6, 78 DA level 9.
  • memLevel is 9, not zlib's default of 8. It matters for large streams.
  • windowBits is 15 with the default strategy, with one exception below.
  • The model, track and font writers fed zlib one file section at a time and called deflate(Z_FULL_FLUSH) between sections. Each flush shows up as an empty stored block, 00 00 FF FF.
  • The zlib was 1.2.4 or older. From 1.2.5.1 on, a full flush rewinds the sliding window, which makes the first bytes after a flush unmatchable. Old zlib kept the window and only cleared the hash table.
  • An empty fixed-Huffman block (10 bits) sometimes appears just before the empty stored block. Old zlib emitted it when the 8 KB output buffer filled during a flush, which happens when the last data block before the flush exceeds about 8,192 bytes.
  • Raging Thunder 2's font02.fnt compressed its palette section with Z_FILTERED and switched back to the default strategy for the pixels. It is the only stream that needs this.
Flush placement: in CNK2 models a flush comes before any chunk of at least about 1 KB (1,032 bytes including its 8-byte header), once about 4.1 KB has built up, and at the end of some FORM groups. That reproduces the flush layout of 95 of the 110 CNK2 model and track streams.

In OmegaStudio

  • Layers are peeled one at a time: PLZP whenever the magic is present, bare zlib whenever the header check passes and the stream inflates. Each layer and its level are remembered.
  • A PLZP's compressed size must equal the entry size minus 12, its uncompressed size must be at most 256 MiB, and it must inflate to exactly that size.
  • An entry whose payload comes back unchanged keeps its original bytes. An edited one is wrapped again in the same layers, at level 9 for a 78 DA layer and level 6 for 78 9C, using .NET's zlib with no section flushes.

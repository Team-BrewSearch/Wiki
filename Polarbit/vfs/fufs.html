A .vfs archive is a FUFS container: a sorted name-hash table pointing into a contiguous payload region. The type of each entry is sniffed from its payload, not stored in the table.

File Layout

offset  size      field
0       4         magic "FUFS"
4       4         0x80000000 | end offset (see below)
8       4         entry count N
12      12*N      entry table: { u32 offset, u32 nameHash, u32 size }
12+12N  ...       payloads, packed back to back

Rules

  • The table is sorted by nameHash, ascending, with no duplicates. A rebuilt archive must keep it sorted.
  • Payloads appear in table order, packed back to back starting right after the table. No padding or alignment.
  • Entries carry no type information. The type is sniffed from the payload.

Name Tables

In CNK2, CNK3D and Krazy Kart Racing the archive ends after the last payload and the field at offset 4 holds the file size with bit 31 set.

The four 2011 archives (Getaway and RT2) append file names:

...  payloads
P    names, NUL-terminated, one per entry in table order
E    u32 byte length of the name block (= E - P)
E+4  zlib stream (78 DA, level 9) of the same name block, sync-flushed and never finished

Here the field at offset 4 holds 0x80000000 | E: it covers the plain names but not the length word or the compressed copy. The compressed copy ends with 00 00 FF FF of a sync flush and has no final block or Adler-32. Names are relative paths with forward slashes, such as data/levels/Track_Coastal_1.pxc, frontend/locale/strings.ben and shaders/blur.fp.

Name Hash

h = 0
for each byte c of the path:
    h = (h * 67 + toupper(c) - 113) mod 2^32

Recovered from the 649 stored names in the 2011 archives. It is case-insensitive. The older archives use the same function — for example, data/lang/lang.bin hashes to the LANG entry in CNK2, CNK3D and KKR.

Recovering Names for Older Archives

unpack names files in two steps:

  1. Every path-like string in the data that ends in a known extension is hashed as-is and with data/ prefixed. These come from XML files, track tables, and texture lists inside models and tracks.
  2. Each directory found in step 1, and each directory in the tool's NAME_DIRS list, is joined with every file name the data mentions, under every extension found in step 1.

A hit only counts when the payload type fits the extension: .png must hold a PNG or PVR, .pvr a PVR, .psn a PSND, .pof and .trk a PIFF file.
